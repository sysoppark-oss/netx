# 국경경비대 — 출국 심사 (첫 판)

AI 에이전트가 저장소에서 일을 마치고 코드를 올릴 때, 세 가지를 규칙으로 맞춰 보고 한 장으로 보여 주는 작은 도구다.

| 이름 | 누가 정하나 | 어디에 있나 |
|---|---|---|
| 비자 | 사람 | 기준점(`main`)의 `.border/visa.toml` |
| 신고 | 에이전트 | 올리는 가지의 `.border/declare.toml` |
| 실제 | git | 기준점에서 갈라진 자리부터 지금까지의 전체 차이 |

- 아무것도 고치거나 지우지 않는다. 보고하고 끝날 때의 값으로 알린다.
- AI를 쓰지 않는다. 규칙만 쓴다.
- NetX의 코드에 기대지 않는다. 이 폴더만 떼어 옮길 수 있다.

## 쓰는 법

```
cd border && cargo build --release
./target/release/border exit --repo .. --base main --head dev
```

기준점에 비자가 아직 없으면 `--visa ../.border/visa.toml`로 시험할 수 있다. 이때 보고서에 "권위가 없다"고 적힌다.

| 끝날 때의 값 | 뜻 |
|---|---|
| 0 | 통과 |
| 1 | 사람 확인 필요 (위험 분류에 걸렸거나, 신고 누락이거나, 신고와 다르게 했다) |
| 2 | 비자 밖 |
| 3 | 검사하지 못함. 통과로 치지 않는다 |

## 신고 파일

```toml
[[declare]]
what = "고침"            # 만듦 · 고침 · 지움
where = "src/App.tsx"    # 파일 하나가 기본. 폴더(`docs/`)나 별표로 적으면 "넓은 신고"로 표시된다
```

신고는 **기준점에서 본 것**으로 적는다. 가지 안에서 새로 만든 파일을 나중에 고쳤어도, 기준점에 없던 파일이면 "만듦"이다.

## 신고했더라도 언제나 맨 위에 보이는 것

| 분류 | 보는 것 |
|---|---|
| 가 | 빌드·시험 때 실행되는 것: `build.rs`, 워크플로, 설치 훅, `scripts/`, `Cargo.toml`의 빌드 스크립트·빌드 의존성·proc-macro, `package.json`의 `scripts` |
| 나 | AI 도구의 지침·설정 파일 |
| 다 | 새 패키지 이름, 등록소가 아닌 곳(git·path)에서 받는 의존성, 바꿔치기 설정, 등록소 주소 파일 |
| 라 | 비자에 적은 "풀지 않는 설정" |
| 바 | 더해진 줄의 보이지 않는 글자, 글자 방향을 바꾸는 문자 |
| 늘 | 비자에 "바뀌면 언제나 사람이 본다"고 적은 경로 |
| 비자 | 비자 파일 자체의 변경 |

비자의 "평소 일"(`[[usual]]`)에 적은 모양의 줄만 바뀐 경우에는 가·라에 걸지 않는다.
그 밖에 새로 나타난 접속 주소, 넓은 신고, 판이 바뀐 패키지 수, 변경이 큰 파일을 알려 준다.

## 못 하는 것

- 평범한 소스 파일 안에 넣은 악의. 사람의 코드 검토가 할 일이다.
- 올라오지 않은 것(추적하지 않는 파일, 로컬 git 설정, 빌드 산출물).
- 에이전트가 작업 중에 직접 밖으로 보내는 것.
- 기준점이 이미 오염된 경우.
- 아직 없는 것: CI 연결, 비밀 모양 검사, 서브모듈·심볼릭 링크·이진 파일 분류.

설계: 프로젝트 문서 「국경경비대 출국 심사 설계 (2판 초안)」.
