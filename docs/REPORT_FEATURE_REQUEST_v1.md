# 상세 보고서 기능 — 공통 규칙과 개발 의뢰 (1판)

- 날짜: 2026-11-14 · 기획: 박정근 · 작성: Claude (통합 설계 세션)
- 근거: 기획자 의뢰 "스토리방화벽, 넷엑스 메뉴별 선택 상세 리포트 생성 기능 개발" (2026-11-14)
- 상태: **1판. 이 문서대로 구현한다.** 세부를 바꿔야 하면 통합프로젝트 폴더에 변경 제안을 올리고 목차의 "바뀐 것"에 한 줄 적는다.
- 읽는 곳: 스토리방화벽 개발 세션은 1·2·3장, NetX 개발 세션은 1·2·4장.
- 기준판 순서와의 관계: 스토리방화벽은 "새 기능보다 설치판을 쓰며 고치기"가 원칙이지만, 이 기능은 기획자가 직접 의뢰한 것이다. 한 번에 한 단계씩(3.3) 넣는다.

## 1. 무엇을 만드나

각 프로그램에 **"보고서 만들기"** 화면을 하나 둔다.

1. 사용자가 **메뉴(구역)를 체크해서 고른다.** 기본은 전부 체크.
2. **기간**을 고른다: 오늘 / 최근 7일 / 최근 30일 / 직접(시작·끝 날짜). 기간이 없는 구역(현재 정책, 내 네트워크 정보)은 "만든 시각 기준"으로 적는다.
3. **가리기**를 고른다(기본 켬, 2.4).
4. [만들기] → 진행 표시와 [취소] → 저장 위치를 사용자가 고른다 → 저장 뒤 [열기] [폴더 열기].
5. 여기에 더해 **한 건짜리 보고서**: 스토리방화벽 사건 카드, NetX 진단 기록 한 건에 [이 건 보고서] 단추. 같은 형식으로 그 한 건만 담는다.

## 2. 공통 규칙 (두 프로그램 모두)

### 2.1 파일 형식

- **HTML 한 파일**이 기본이다. 브라우저로 열고, 브라우저 인쇄로 PDF를 만든다. 인쇄용 CSS(`@media print`)로 구역마다 쪽을 나눈다.
- 선택으로 **원자료 JSON**을 같은 이름으로 함께 저장한다(`…-data.json`). 모양은 2.6.
- 파일 이름: `<프로그램>-report-<YYYYMMDD-HHMMSS>.html` (예: `storyfirewall-report-20261114-051200.html`).

### 2.2 보안 (보고서는 바깥에서 온 글자를 담는다)

1. **모든 글자를 HTML 바꿔 쓰기**(`& < > " '`, 제어 문자 제거). 도메인, 파일 이름, 명령줄, 장비 배너, 프로세스 이름은 공격자가 고를 수 있는 글자다. NetX의 `history.rs`의 `esc`와 같은 규칙을 쓴다.
2. **스크립트를 넣지 않는다.** `<script>`, 이벤트 속성(`onclick` 등), `javascript:` 링크 모두 없음. 파일 맨 앞에 `<meta http-equiv="Content-Security-Policy" content="default-src 'none'; style-src 'unsafe-inline'; img-src data:">`.
3. **바깥 자원을 불러오지 않는다.** 글꼴·그림·지도는 파일 안에 넣는다(인라인 SVG 또는 `data:` 그림). 보고서를 여는 순간 어딘가로 접속하면 안 된다.
4. 바깥 주소(도메인, URL)는 **링크로 만들지 않고 글자로만** 적는다.
5. 단위 시험: 위 글자들이 섞인 값을 넣어 만든 보고서에 실행될 수 있는 태그·속성이 하나도 없는지 확인(무작위 입력 시험 포함).

### 2.3 보내지 않는다

- 보고서는 **사용자가 고른 위치에 파일로만** 저장한다. 업로드, 메일 보내기, 클라우드 저장 단추를 두지 않는다.
- 만든 사실을 어디에도 알리지 않는다. 각 프로그램의 감사 로그에는 "보고서를 만듦(구역, 기간, 가리기 여부, 저장 경로)"을 남긴다.

### 2.4 가리기 (기본 켬)

남에게 보여 줄 때를 위한 것이다. 켜면 아래를 가린다.

| 가리는 것 | 표시 | 비고 |
|---|---|---|
| 내부 IP (사설 대역, 링크 로컬) | `192.168.x.x` → `내부-1`, `내부-2` | 같은 주소는 같은 번호(보고서 안에서 일관) |
| MAC 주소 | 앞 3바이트(제조사)만 남김 `aa:bb:cc:**:**:**` | |
| PC 이름, 사용자 이름 | `PC-1`, `사용자` | 경로 `C:\Users\<이름>\…` 안의 이름도 |
| 이 PC의 공인 IP | `내 공인 IP` | |
| SNMP 커뮤니티 문자열·암호·키 | **항상 뺀다** (가리기를 꺼도) | 애초에 보고서에 싣지 않는다 |

- **바깥 목적지 주소·도메인은 가리지 않는다.** 보고서를 보는 사람이 판단해야 할 대상이기 때문이다.
- 가리기를 끄면 저장 전에 한 번 확인: "내부 주소, PC 이름이 그대로 들어갑니다."
- 보고서 머리에 가리기 여부를 적는다.

### 2.5 넣지 않는 것

- **말씀 구절을 넣지 않는다**(공통 규칙: 내보내는 파일에는 넣지 않는다). 헌정 문구도 넣지 않는다. 바닥글에 "<프로그램> <판> — 맑은물속교회가 무료로 나눕니다" 한 줄과 소스 주소는 둔다.
- 사용자 대화 내용, AI 도구의 대화 기록, 패킷의 페이로드(내용)는 넣지 않는다.

### 2.6 공통 머리와 원자료 모양 (나중에 안디옥 통합 보고서로 합칠 수 있게)

HTML 머리에 표로, JSON에는 아래 모양으로 같은 내용을 싣는다.

```json
{
  "report": "antioch.report/1",
  "program": "storyfirewall",
  "version": "0.1.7",
  "generated_at": "2026-11-14T05:12:00+09:00",
  "period": {"from": "2026-11-07T00:00:00+09:00", "to": "2026-11-14T05:12:00+09:00"},
  "masked": true,
  "sections": [
    {"id": "incidents", "title": "인시던트", "count": 12, "shown": 12, "items": [ ... ]}
  ]
}
```

- `count`는 기간 안 전체 건수, `shown`은 보고서에 실은 건수. 다르면 HTML에 "전체 N건 중 상위 M건"을 적는다.
- 구역 `id`는 아래 3장·4장의 표에 적힌 것을 쓴다. 구역 안 `items`의 모양은 각 프로그램이 정하고 자기 저장소 문서에 적는다.
- 머리 문구(고정): "이 보고서는 만든 시각까지 이 PC가 기록한 사실을 모은 것이며, 판정이 아닙니다."

### 2.7 크기와 속도

- 구역마다 상한: 표 2,000행. 넘으면 정렬 기준 상위 2,000행과 "전체 N건"을 적는다.
- 만드는 동안 화면이 멈추지 않는다(진행 표시, 취소). 취소하면 만들던 파일을 남기지 않는다.
- 시험: 실데이터 규모(원시 사건 수십만 건, 기간 30일)에서 1분 안에 끝남. 넘으면 그 시간을 문서에 적고 구역별 상한을 낮춘다.

## 3. 스토리방화벽

### 3.1 구역 (메뉴와 같은 순서)

| 구역 id | 메뉴 | 싣는 것 |
|---|---|---|
| `summary` | 대시보드 | 기간 요약: 연결 수, 처음 본 목적지 수, 열린·닫힌 사건 수, 차단 수, 수집기 상태 |
| `network` | 네트워크 | 프로세스별 연결·사용량 상위, 목적지 국가·조직 상위(오프라인 DB 기준이라고 적음), 들어오는 연결을 받은 포트 |
| `incidents` | 인시던트 | 사건마다 이야기 문장, 근거 사건 시각, 관련 프로세스·파일·목적지. 마인드맵 그림(선택, 인라인 SVG) |
| `blocked` | 차단 기록 | 차단 건수(규칙별), 상위 차단 목적지, 기준(어느 규칙까지 셌는지) |
| `installs` | 설치 이력 | 기간 안에 나타난 실행 파일: 서명 여부, 인터넷 출신(MOTW), 자동 실행 등록 |
| `agents` | AI 에이전트 감시 | 도구별 접속지, 실행한 프로그램, 만든 파일 |
| `policy` | 정책 | 지금 적용된 규칙 목록, 기한부 규칙의 남은 시간, 최근 변경 이력 |
| `health` | 설정 › 진단 | 수집기·서비스 상태, 누락 경고, 판 정보 |

- **이야기 문장 규칙을 그대로 지킨다**: 의도를 단정하지 않는다("몰래 보내려 했다" 금지). 화면 문장을 그대로 싣고 보고서용으로 다시 쓰지 않는다.
- Defender 탐지 기록이 있으면 `incidents` 안에 함께 싣는다(해설 그대로).

### 3.2 구조와 권한

- **서비스는 파일을 쓰지 않는다.** 화면(일반 권한)이 기존 조회 메서드(`Role::User`)로 자료를 받아 HTML을 만들고, 사용자가 고른 위치에 쓴다. 보고서 때문에 서비스에 새 쓰기 권한을 주지 않는다.
- 조회가 무거우면 서비스에 **읽기 전용** 묶음 조회 메서드를 하나 더할 수 있다(`report.collect`, `Role::User`). 읽기 경로에서 DB에 쓰지 않는다는 원칙을 지킨다.
- HTML 만드는 코드는 순수 함수로 떼어(예: `crates/report` 또는 화면 쪽 모듈) Linux에서 시험한다.

### 3.3 순서 (한 번에 한 단계)

1. 보고서 화면 + 공통 머리 + `incidents`, `blocked`, `policy` + 사건 카드의 [이 건 보고서].
2. `summary`, `network`, `installs`.
3. `agents`, `health`, 마인드맵 그림, 원자료 JSON.

단계마다 노트북에 설치해 실제로 만들어 보고, 맥락을 모르는 검수 에이전트가 보고서 파일을 2장 규칙(바꿔 쓰기, 바깥 자원, 가리기)과 대조한다.

## 4. NetX

### 4.1 구역

| 구역 id | 메뉴 | 싣는 것 |
|---|---|---|
| `mynet` | 내 네트워크 | 어댑터, 내부·공인 주소, 게이트웨이, DNS (가리기 적용) |
| `history` | 최근 진단 | 고른 기록(기본 기간 안 전부): 입력, 계획, 단계별 결과와 판정, 브리핑 |
| `topology` | 구성도 | 구성도 그림(인라인 SVG), 장비 목록(이름, 종류, 관리 주소, 포트 연결 관계) |
| `capture` | 캡처 분석 | 고른 캡처의 요약, 찾은 문제, 상위 대화. 패킷 내용은 싣지 않는다 |
| `manual` | 직접 명령 | 실행한 명령과 종료 상태, 출력 앞부분(줄 수 상한) |
| `terminal` | 터미널 | **기본 체크 해제.** 체크하면 경고: "장비 설정과 암호가 출력에 섞여 있을 수 있습니다." 세션 목록(대상, 시각)만 기본, 출력은 한 번 더 체크해야 싣는다 |
| `audit` | 감사 로그 | 실행 확인, 연동으로 받은 의뢰(스토리방화벽에서 온 진단 대상 포함) |

### 4.2 기존 기능과의 관계

- 지금 있는 "최근 진단 → 보고서 파일 내보내기"(`history.rs`의 `report`, 가리기 `mask`)와 "보고서 가져오기"를 **이 화면의 `history` 구역으로 흡수**한다. 가져오기는 그대로 둔다(가져올 때 2.2의 규칙으로 다시 바꿔 쓰는지 시험한다).
- 기존 보고서 파일과 새 보고서가 둘 다 가져오기에 통과해야 한다.

### 4.3 순서

1. 보고서 화면 + 공통 머리 + `history`(기존 흡수), `mynet`, `audit`.
2. `topology`, `capture`, `manual`.
3. `terminal`, 원자료 JSON.

`dev`에서 노트북 확인 뒤 `main`에 올린다(지금 방식 그대로).

## 5. 정하지 않은 것 (개발을 막지 않음)

- 두 프로그램 보고서를 한 파일로 합치는 "안디옥 통합 보고서"는 통합 화면이 생긴 뒤에 한다. 2.6의 원자료 모양이 그 준비다.
- 정해진 시각에 보고서를 자동으로 만드는 기능은 넣지 않는다(필요하면 다음 판에서).
- 영어 보고서는 언어 선택(설계 문서 11.9)이 들어간 뒤 화면 언어를 따른다.
