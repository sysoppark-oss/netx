# 모음함 1단계 — 구현 기록과 정한 값 (1판)

근거: 통합프로젝트 「변경 제안 — NetX 사이 진단 결과 모으기("모음함")와 다른 지점 확인 의뢰 (2판)」(확정 2026-11-15)의 5·6·7·8·10장.
코드: `src-tauri/src/collect/` (독립 모듈), 화면 `src/components/CollectView.tsx`, `src/lib/collect.ts`.

## 1. 모듈의 경계

| 파일 | 하는 일 | NetX에 기대는 것 |
|---|---|---|
| `wire.rs` | 한 건의 모양(OCSF), 다듬기, 가리기 | 없음 |
| `key.rs` | 기기 키, 지문, 일회용 코드, 코드 증명, 확인 숫자 | 없음 |
| `store.rs` | 모음함 DB와 보낼 함 DB (SQLite WAL) | 없음 |
| `net.rs` | 테일스케일 주소에서 듣기, TLS 상호 인증, 주고받는 줄 | 없음 |
| `mod.rs` | 설정, 짝 맺기 창, 끝난 진단 받기(`Hub::submit`) | 없음 |
| `app.rs` | Tauri 명령, 감사 로그, [최근 진단] 기록 → 한 건 변환 | **여기만** NetX의 것을 쓴다 |

NetX의 화면·실행 엔진·검증기를 부르지 않는다. NetX가 넘기는 것은 끝난 진단 한 건(`wire::Finished`)뿐이다. 관제로 뗄 때 `app.rs`만 바꾼다.
2단계(다른 PC로의 조회 의뢰)의 통로는 없다. 모음함은 모르는 줄을 받으면 접속을 끊는다(시험 `session_survives_garbage_and_never_speaks_first`).

## 2. 통신 (5장)

- 듣기: 이 PC의 테일스케일 주소(100.64.0.0/10) 하나에만 묶는다. 주소가 없거나 묶지 못하면 듣지 않는다. 주소가 바뀌면 닫고 다시 묶는다. 접속해 온 주소가 그 대역이 아니면 받지 않는다. 보내는 쪽도 그 대역이 아닌 주소로는 걸지 않는다(설정 파일을 손으로 고쳐도).
- TLS 1.3 상호 인증. 인증서는 PC마다 스스로 만든 것 하나(ECDSA P-256), 인증 기관 없음. PC의 id = 공개 키(SubjectPublicKeyInfo)의 SHA-256.
- 보내는 쪽은 저장한 지문과 다른 모음함이면 인증에서 끊는다(자료를 보내기 전). 모음함은 인증 뒤 지문이 짝(active)이 아니면 `hi`에서 거절한다.
- 인증 10초, 동시 접속 8개, 한 줄 약 260KB, 줄 사이 150초가 상한이다.
- 한 줄 JSON. 보내는 쪽 → 모음함: `pair`, `hi`, `alive`(60초마다), `dropped`, `put`. 모음함 → 보내는 쪽: 답(`pair.wait`, `pair.ok`, `pair.no`, `hi`, `ok`, `ack`, `no`)뿐. 모음함이 먼저 보내는 줄은 없다.

### 짝 맺기

1. 모음함에서 [새 PC 짝 맺기] → 일회용 코드(31자 가운데 10자, 약 50비트), 2분, 틀린 입력 5번이면 버림. 코드가 맞은 뒤에는 다른 상대가 같은 코드로 들어오지 못한다.
2. 보내는 PC가 주소와 코드를 넣는다. 코드는 그대로 보내지 않고, 코드와 두 지문에서 만든 키(HMAC-SHA256을 6만 번 되풀이)의 증명을 보낸다. 모음함도 같은 키의 증명으로 답한다(코드를 모르는 가짜 모음함을 가린다).
3. 양쪽 화면에 확인 숫자(두 지문에서 계산한 8자리)와 상대 이름·주소가 뜬다. 모음함에서 [짝 맺기 승인]을 눌러야 지문이 저장된다.
4. 짝 끊기: 보내는 쪽 [짝 끊기](보내기도 꺼지고 보낼 함을 비운다), 모음함 쪽 [짝 끊기]·[받기 멈춤].

### 한 건의 모양 (5장 4번)

OCSF **Scan Activity**(category_uid 6, class_uid 6007, activity_id 2 = Completed, type_uid 600702), 판 1.3.0. 진단은 "검사 작업 하나의 시작·끝·결과"라 이 클래스가 가장 가깝다(Network Activity는 연결 한 건, Finding은 탐지 한 건을 뜻한다).

| OCSF 칸 | 값 |
|---|---|
| `time`, `start_time`, `end_time`, `duration` | 진단 시각(보낸 PC의 시계, 밀리초) |
| `severity_id` | 정상 1, 주의 3, 위험 4, 판정 없음 0 |
| `message` | 요약 문장 |
| `num_detections` | 주의·위험 판정이 난 단계 수 |
| `metadata.uid`, `metadata.sequence` | `<PC id>:<순번>`, 순번(그 PC에서 1씩 늘어남) |
| `device.uid` | 보낸 PC의 id |
| `scan.name`, `scan.uid` | 진단 제목, 진단 종류(레시피 id) |
| `unmapped.netx` | `v`(1), `kind`, `target`, `verdict`, `masked`, `summary`, `steps[]`(순서, 제목, 도구, 명령줄, 상태, 종료 코드, 걸린 시간, 판정, 해석 문장) |

**원본 출력은 보내지 않는다.** 캡처 파일, 구성도 그림, 터미널 내용, 스토리방화벽의 사건 기록도 보내지 않는다.

## 3. 11장에서 정한 값

1. **기기 키 보관:** Windows 자격 증명 관리자(사용자 계정으로 암호화, 이미 쓰는 `keyring`)에 PKCS#8로 둔다. 인증서(공개)는 자료 폴더 `collect/device.crt`. **TPM은 이번에 쓰지 않았다** — TLS 서명을 TPM 키로 하려면 Windows CNG에 맞춘 서명기를 따로 짜야 해서, 관제(서비스)로 뗄 때 다시 본다. 지금 방식은 같은 사용자 권한의 악성 프로그램이 키를 꺼낼 수 있다(6장의 한계와 같은 범위).
2. **보관 기한 기본값:** 90일(받은 시각 기준, 1~730일로 바꿀 수 있음). 한 시간마다 지난 것을 지운다.
3. **포트와 방화벽:** TCP **49317**(동적 포트 범위). NetX는 방화벽 규칙을 스스로 만들지 않는다(관리자 권한이 필요하고, 시스템 보안 설정을 앱이 몰래 바꾸지 않기 위해). 처음 들을 때 Windows가 묻는 허용 창에서 사용자가 허용한다. 권장 규칙: 프로그램 `netx.exe`, 들어오는 TCP 49317, 로컬 주소 = 이 PC의 테일스케일 주소, 원격 주소 = 100.64.0.0/10. **스토리방화벽 가드:** NetX의 들어오는 49317은 원격 주소가 100.64.0.0/10일 때만 정상으로 본다(그 밖의 주소에서 오는 것은 NetX가 어차피 받지 않는다). 보내는 PC에서는 `netx.exe`가 100.64.0.0/10의 49317로 나가는 연결이 생긴다.
4. **가린 주소 묶기:** 가명으로 한다. 내부 주소는 `내부-ab12cd`(PC마다 다른 비밀 값으로 만든 HMAC의 앞 3바이트)로 바뀌고, 같은 주소는 그 PC에서 언제나 같은 가명이다. 모음함에서 그 PC 안의 같은 대상끼리는 묶이고, 다른 PC의 같은 내부 주소와는 묶이지 않으며, 원래 주소로 되짚을 수 없다. MAC은 뒤 세 자리를 가리고, PC 이름·사용자 이름·이 PC의 공인 주소는 글자로 바꾼다. 이 PC 자신의 모음함에 넣는 사본은 가리지 않는다(밖으로 나가지 않으므로).
5. **서비스 분리:** 하지 않았다. NetX가 켜져 있을 때만 로그인한 사용자 권한으로 듣는다. 관제로 뗄 때 정한다.
6. **PAKE:** 쓰지 않았다. 대신 (가) 코드 증명을 두 지문에 묶고 느리게 만들어, 받아 적은 통신으로 코드를 맞혀 보기 어렵게 했고 (나) 확인 숫자를 8자리로 했고 (다) 사람이 승인한다. 새 라이브러리를 늘리지 않으려는 판단이며, 관제로 뗄 때 다시 본다.

## 5. 모음함의 메뉴 (8장)

- **받은 결과:** 보내는 PC 목록(미확인·멈춤 표시, 받기 멈춤·다시 받기·짝 끊기), 경고·빠진 구간·받지 않던 구간, 목록과 필터(보낸 PC, 기간, 대상, 진단 종류, 판정). 한 번에 200건.
- **종합 분석:** 요약 표(`sum_target`, `sum_hour`)를 5분마다 주기 작업이 다시 만들고, 화면은 그 표만 읽는다(조회가 DB에 쓰지 않는다). 날짜별 추이(30일), 주의·위험이 나온 시각대, 대상별로 PC마다의 건수와 마지막 판정. "여러 PC가 본 대상", "PC마다 판정이 다른 대상", "한 PC에서만 나온 대상"(6장)을 구별한다. 가명(`내부-…`)은 PC마다 따로 센다.
- **보고서:** 상세 보고서에 "모음함" 구역(기본 해제). 진단 시각, 보낸 PC, 진단, 대상, 판정, 요약. 이 PC에서 가리기를 켜면 받은 글자도 같은 규칙으로 가린다. 원자료 JSON에도 실린다.
- **받은 글자:** 저장할 때와 읽을 때 모두 제어 문자·글자 방향 문자를 지우고 길이를 자른다. 화면은 글자로만 그린다(링크·서식 없음).
- AI 요약은 1단계에 넣지 않는다(8장 7번).

## 6. 노트북에서 확인할 것

PC 한 대로: [📥 모음함] → "이 PC를 모음함으로" 켜기 → 듣는 주소가 100.x로 뜨는지 → 진단 하나 실행 → "받은 결과"에 이 PC의 건이 보이는지 → 5분 뒤 "종합 분석" → 보고서의 "모음함" 구역.
PC 두 대로(둘 다 이 판, 같은 테일스케일): 모음함 PC에서 [새 PC 짝 맺기] → 보내는 PC에서 주소·코드 → 두 화면의 확인 숫자 → [짝 맺기 승인] → 보내는 PC에서 [보내기 켜기] → 진단 → 모음함에 도착.

## 7. 거점 관제로 이름 바꿈, 예약 수집 (2026-11-19)

- 화면에서는 "모음함"을 **거점 관제**, 받는 PC를 **관제 PC**, 보내는 PC를 **거점**이라 부른다. 이 문서의 "모음함"은 같은 것이다. 규약·포트·DB·명령 이름은 그대로다.
- 근거: 통합프로젝트 「변경 제안 — 거점 관제: 예약 수집과 거점 관리 대시보드 (2판, 확정)」.
- **접속 내역**: 관제 PC의 `conns` 표(끝난 까닭은 정해진 낱말). 명령 `collect_site`.
- **수집 자료**: 종류 `inventory.system`, `inventory.software`. 봉투는 진단 결과와 같고 `unmapped.netx.data`에 `{"system":{os, build, host, cpu, cores, mem_total, mem_used, disks:[{name,total,free}], uptime_secs, netx, tailnet}}` 또는 `{"software":{"programs":[{name, version, publisher, installed}], "cut":bool}}`. 가리기를 켜면 `host`는 비운다. 모양이 아닌 `data`는 버리고 건은 받는다.
- **거점의 동의**: 설정 `inventory`(항목 → `{on, every}`), 기본 비어 있음. 켠 항목만, 보내기나 받기가 켜져 있을 때만 읽는다. 명령을 실행하지 않는다(운영체제 값과 Windows "프로그램 제거" 등록부를 읽기만 한다).
- **수집 예약표**: 관제 PC의 `hi` 답에 `"plan":true`. 그때만 거점이 `{"t":"plan?","have":판,"on":[승인한 항목]}`을 묻고, 관제 PC는 `{"t":"plan","rev":판,"items":[{"what","every"}]}` 또는 `{"t":"ok"}`로 답한다. 관제 PC는 먼저 보내지 않는다. 거점은 정해진 항목 이름과 한도 안의 주기만 남기고, 사람이 켠 항목에만 그 주기를 쓴다. 짝을 끊으면 예약표를 버린다.
- 한도: 시스템 15분, 프로그램 6시간, 가장 뜸하게 7일, 프로그램 600개, 예약표 항목 16개.
- **바로 수집**: 거점 PC의 [지금 수집](명령 `collect_inventory_run`, 켠 항목만). 관제 PC의 [바로 수집](명령 `collect_plan_now`)은 예약표 답에 `"now":[{"what","at"}]`를 실어, 거점이 사람이 켠 항목만 표시 하나에 한 번(1분에 한 번까지) 바로 수집하게 한다. 거점은 20초마다 예약표를 묻는다(`PLAN_EVERY`).
- **네트워크 속도**(`inventory.speed`, `collect/speed.rs`): 고정 주소 `https://speed.cloudflare.com`의 `/__down?bytes=N`, `/__up`으로 잰다(대역폭 측정 레시피를 쓰지 않는다 — WSL 없는 거점에서도 돌게). 자료 `{"speed":{down_mbps, up_mbps, latency_ms, server, bytes}}`. 한도 1시간, 기본 6시간, 한 번에 15~50MB, 실패하면 10분 뒤 다시(`RETRY_GAP`), 진단 중에는 미룸. 약관상 자동 측정 허용 여부는 확인하지 못했다(변경 제안 4판 10장).
