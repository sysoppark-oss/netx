# 넷엑스(NetX) 최종 통합 설계서

- 문서 버전: 1.0 (초기 설계 확정본)
- 작성일: 2026-11-10
- 기획: 박정근
- 용도: 실제 개발안 수립의 기준 문서. Claude와 Gemini 양쪽에 그대로 전달한다.
- 저장소: GitHub `sysoppark-oss/netx` (공개)
- 표기: **[확정]** 은 기획자가 결정한 사항, **[제안]** 은 아직 선택하지 않은 아이디어, **[검증]** 은 노트북 실기 확인이 필요한 사항이다.

---

## 1. 넷엑스란 무엇인가

**넷엑스는 현업 네트워크·시스템 엔지니어가 쓰는 도구를 한곳에 모아 두고, 상황을 말하면 어떤 도구를 어떤 옵션으로 쓸지 제안받아 바로 실행하는 Windows용 통합 작업대다.**

세 가지를 동시에 만족해야 한다.

1. **전부 모여 있다.** 진단 도구, 장비 접속 터미널, 파일 전송, 계산기까지 네트워크 유지보수와 검증에 필요한 도구가 한 프로그램 안에 있다.
2. **자유롭게 쓴다.** 모든 도구의 모든 옵션을 제한 없이 조합할 수 있다. 정해진 버튼만 누르는 프로그램이 아니다.
3. **상황이 도구를 부른다.** 사용자가 상황을 입력하면 의도를 파악해 해결 가능한 도구의 우선순위를 제시하고, 도구마다 가장 적합한 옵션 조합을 이유와 예상 결과와 함께 만들어 준다. 실행을 누르면 바로 결과가 나온다.

초기 구상은 "9종 도구 원클릭 대시보드"였으나, 논의를 거쳐 위 정의로 확장되었다. 9종과 원클릭 6종은 이 구조 안의 일부로 흡수된다.

## 2. 핵심 루프 [확정]

넷엑스의 모든 기능은 아래 한 줄의 흐름을 중심으로 돈다.

```
상황 입력 → 의도 파악 → 도구 우선순위 → 도구별 옵션 조합(이유·예상 결과) → [실행] → 결과 → 판정
```

### 2.1 단계별 동작

| 단계 | 동작 |
|---|---|
| 상황 입력 | 화면 최상단 옴니박스에 자연어(텍스트, 추후 음성)로 입력한다. 예: "회사 홈페이지가 가끔 느려요" |
| 의도 파악 | AI가 증상을 분류한다. 예: "간헐적 웹 지연, 원인 구간 특정" |
| 도구 우선순위 | 해결 가능한 도구를 순서대로 제시한다. 빠르고 가벼운 도구가 먼저, 무겁거나 침투적인 도구(패킷 캡처, 포트 스캔)는 뒤에 온다. |
| 옵션 조합 | 도구마다 가장 적합한 옵션 배열을 만든다. **왜 이 옵션인지**와 **어떤 결과를 보게 될지**를 함께 적는다. |
| 실행 | [전체 실행], [이것만 실행], [옵션 수정] 중 하나를 누른다. 실행 버튼이 사람의 최종 확인이다. AI는 스스로 실행하지 않는다. |
| 결과 | 상단에 AI 브리핑(신호등 🟢/🔴 포함), 하단에 원본 출력(접이식)을 보여 준다. 도구에 맞는 시각화가 있으면 함께 띄운다. |
| 판정 | 실제 결과를 "예상 결과"와 대조해 결론을 낸다. 필요하면 다음 단계 도구를 다시 제안한다. |

### 2.2 제안 카드 예시

```
의도: 간헐적 웹 지연 (원인 구간 특정)

① curl  -o /dev/null -s -w "dns:%{time_namelookup} tcp:%{time_connect}
         tls:%{time_appconnect} ttfb:%{time_starttransfer}" https://대상
   이유: 지연이 DNS·연결·TLS·서버 응답 중 어디서 생기는지 단계별 시간으로 쪼갠다.
   예상: ttfb만 길면 서버(L7) 문제, tcp가 길면 네트워크 문제.

② mtr   -rwbzc 50 대상
   이유: 50회 측정으로 간헐적 손실을 잡고, AS 번호로 통신사 구간을 구분한다.
   예상: 특정 홉부터 Loss가 누적되면 그 구간이 원인.

③ dig   +stats +trace 대상
   이유: DNS 응답 지연이나 위임 경로 문제를 확인한다.

[▶ 전체 실행]  [①만 실행]  [옵션 수정]
```

### 2.3 실행 계획 데이터 형식

AI는 아래 JSON만 반환한다. 백엔드는 이 JSON을 도구 스키마로 검증한 뒤에만 실행 후보로 올린다.

```json
{
  "intent": "intermittent_web_latency",
  "summary": "간헐적 웹 지연, 원인 구간 특정",
  "target": "example.com",
  "steps": [
    {
      "order": 1,
      "tool": "curl",
      "args": ["-o", "/dev/null", "-s", "-w", "dns:%{time_namelookup} ...", "https://example.com"],
      "reason": "지연 구간을 단계별 시간으로 분해",
      "expect": "ttfb만 길면 L7, tcp가 길면 네트워크",
      "risk": "safe",
      "needs_root": false
    }
  ]
}
```

- `tool`과 `args`는 항상 분리된 배열이다. 문자열 한 줄로 된 명령은 받지 않는다.
- `risk`는 `safe`, `caution`, `danger` 3단계다. 스키마에 정의된 옵션 위험도에서 백엔드가 다시 계산하며, AI가 적어 준 값은 믿지 않는다.

## 3. 사용자 등급 [확정]

사용자가 직접 자기 수준을 고른다. 상단에서 언제든 바꿀 수 있다. 같은 상황을 입력해도 등급에 따라 제안의 깊이, 설명 말투, 허용 범위가 달라진다.

| 등급 | 화면에 보이는 것 | 옵션 수정 | 위험 기능 |
|---|---|---|---|
| 일반사용자 | 쉬운 말 결과와 해결 방법만. 명령어·옵션은 숨김 | 불가 | 잠금 |
| 초급 엔지니어 | 도구 우선순위와 옵션 조합, 옵션별 자세한 해설(학습용) | 안전 옵션 안에서만 | 잠금 |
| 중급 엔지니어 | 전체 옵션 패널, 파이프라인 빌더 | 자유 | 경고 후 실행 |
| 고급 엔지니어 | 전체 도구·옵션, 원본 출력 기본 펼침, 설명은 간결하게 | 자유 | 확인 후 실행 |
| 전산관리자(OP) | 고급 + 운영 기능(스냅샷 비교, 정기 점검, 프로세스 종료, 실행 이력·감사 로그, 등급 관리) | 자유 | 확인 후 실행 |

스토리방화벽에서 호출된 경우에는 등급과 관계없이 모든 기능이 열린다(8장).

## 4. 도구 창고

### 4.1 원칙

- 도구 개수를 코드에 고정하지 않는다. **도구 레지스트리** 구조로 만들고, 스키마 파일 하나를 추가하면 새 도구가 들어온다.
- 도구마다 **실행 위치**가 다르다. 리눅스 도구는 WSL2에서, Windows 본체를 봐야 하는 도구와 장비 접속은 Windows 네이티브로 실행한다(10장).

### 4.2 1차 도구 9종 [확정]

실무 Top 10 가운데 PC에서 실행 가능한 9종이다.

| 도구 | 용도 | 대표 옵션 |
|---|---|---|
| ping / fping | 연결성, 지연, 서브넷 다중 핑 | `ping -c`, `fping -a -g` |
| tcpdump (tshark) | 패킷 캡처와 분석 | `-i`, `-c`, `-w`, `-n`, `-X`, 필터식 |
| mtr | 실시간 경로 추적, 홉별 손실률 | `-r`, `-c`, `-w`, `-b`, `-z` |
| ss (netstat) | 소켓, 포트, 연결 상태 | `-tulpn` |
| dig | DNS 질의와 응답 분석 | `+short`, `+trace`, `+stats` |
| nc (telnet) | 포트 개방 확인, TCP/UDP 시험 | `-vz` |
| curl | HTTP/HTTPS, 헤더, TLS | `-I`, `-v`, `-k`, `-s`, `-w` |
| lsof | 포트를 점유한 프로세스 추적 | `-i :포트` |
| iperf3 | 대역폭, 지터 측정 | `-c`, `-t`, `-P`, `-u` |

Cisco IOS `show` 명령어는 PC용 프로그램이 아니라서 진단 도구 목록에서는 빠지지만, **넷엑스 터미널(7장)로 실제 장비에 접속해 사용한다.**

### 4.3 확장 도구 [제안, 우선 5종 권장]

| 범주 | 도구 | 비고 |
|---|---|---|
| 스캔·보안 점검 | **nmap**, masscan, arp-scan | arp-scan은 핑을 막은 장비도 찾는다 |
| 인터페이스·라우팅 | **ip**(addr/route/neigh), ethtool, LLDP 조회 | ethtool은 WSL2 가상 NIC에서 제한적 |
| DNS·인증서 | **openssl s_client**, whois, kdig | 인증서 체인·만료일·SNI 검증 |
| 경로·지연 심화 | tcptraceroute, hping3, paris-traceroute | hping3은 위험 등급 관리 필요 |
| 실시간 트래픽 | iftop, nload, **nethogs**, **tshark**, ngrep | nethogs는 프로세스별 트래픽 |
| 장비 관리 | snmpwalk, snmpget | 장비 상태 조회 |
| Windows 네이티브 | netstat -ano, Get-NetTCPConnection, Test-NetConnection, Resolve-DnsName, pathping, pktmon, netsh wlan | Windows 본체 진단용 |

굵게 표시한 nmap, ip, openssl s_client, tshark, nethogs와 Windows 네이티브 2종(Get-NetTCPConnection, pktmon)을 우선 추가하기를 권한다.

### 4.4 도구 옵션 스키마 (`tools/*.json`)

옵션 패널, 자동완성, AI 제안, 안전 검증이 모두 이 사전 하나를 기준으로 동작한다. 프로젝트의 심장이다.

```json
{
  "tool": "tcpdump",
  "title": "패킷 캡처",
  "engine": "wsl",
  "needs_root": true,
  "streaming": true,
  "categories": ["캡처", "L2-L7"],
  "options": [
    {"flag": "-i", "type": "enum_dynamic", "source": "interfaces", "label": "인터페이스", "group": "입력"},
    {"flag": "-c", "type": "number", "label": "캡처할 패킷 수", "default": 100, "min": 1, "group": "제한"},
    {"flag": "-n", "type": "boolean", "label": "DNS 이름 변환 안 함", "group": "출력"},
    {"flag": "-X", "type": "boolean", "label": "16진수와 ASCII로 내용 표시", "group": "출력"},
    {"flag": "-w", "type": "path", "label": "pcap 파일로 저장", "risk": "caution", "path_scope": "captures", "group": "저장"}
  ],
  "positional": [{"name": "filter", "type": "bpf", "label": "필터식", "example": "port 443 and host 192.168.0.50"}],
  "conflicts": [["-w", "-X"]],
  "viz": "packet_highway",
  "min_level": "junior"
}
```

- `type`: boolean, number, string, enum, enum_dynamic, path, host, port, cidr, bpf.
- `risk`: 옵션 단위 위험도. 파일 쓰기, 연결 수신 대기, 대량 스캔, 프로세스 종료는 `caution` 이상이다.
- `engine`: `wsl`, `windows`, `builtin`(넷엑스 내장 구현) 중 하나.
- 옵션 설명은 모두 한글로 적는다. 자동완성 팝업과 옵션 패널이 같은 문구를 쓴다.
- 목표는 각 도구 매뉴얼의 **모든 옵션**을 담는 것이다. 초기에는 핵심 옵션부터 채우고, 스키마에 없는 옵션은 고급·OP 등급이 "직접 입력"으로 넣을 수 있게 한다(값 검증은 동일 적용).

## 5. 화면 구성

### 5.1 전체 틀

- **상단:** 옴니박스(상황 입력), 등급 선택, Easy/Expert 전환 토글
- **좌측:** 상황 레시피 목록(Easy), 도구 아이콘 툴바(Expert)
- **중앙:** 제안 카드, 파이프라인 조립 영역, 시각화
- **우측:** 동적 옵션 패널(슬라이드), AI 해설 사이드바
- **하단:** 실시간 명령어 미리보기, 원본 출력 터미널(접이식)
- 테마는 깊은 다크 모드(`#0F172A` 수준)가 기본이다.

### 5.2 Easy 모드: 상황 레시피 [확정]

긴급할 때 입력 없이 한 번에 누르는 조합형 버튼이다. 원클릭 6종은 "저장된 레시피"이며, 사용자가 만든 조합도 같은 방식으로 버튼이 된다.

| 레시피 | 입력 | 실행 조합 | 결과 표시 |
|---|---|---|---|
| 🌐 웹 장애 진단 | URL | `dig +short` → `nc -vz IP 443` → `curl -Ivks https://URL` | DNS / 포트 / HTTP 상태 신호등, 인증서 만료일 |
| 📉 라우팅 지연 분석 | 목적지 | `mtr -r -c 10` + `ping -c 5` 병렬 | 손실이 시작되는 홉을 붉게 강조, 노선도 뷰 |
| 🔍 서브넷 장비 스캔 | 대역 | `fping -a -g 대역` | 소나 레이더 뷰, 장비 카드. 더블 클릭 시 핑 모니터링 창 |
| 🚪 포트 점유 추적 | 포트 번호 | `ss -tulpn`(내장 필터) + `lsof -i :포트` | "8080은 Java(PID 4321)가 점유 중" 문구와 [강제 종료] |
| 🚀 대역폭 측정 | iperf3 서버 | `iperf3 -c IP -t 10 -P 4` | 자동차 계기판 애니메이션(Mbps) |
| 👁️ 트래픽 퀵 캡처 | 인터페이스, 포트 | `tcpdump -i IF port P -c 100 -w 파일.pcap` | 저장 완료 알림 |

### 5.3 Expert 모드 [확정]

- **동적 옵션 패널:** 도구를 고르면 그 도구의 옵션이 범주별로 정리된 패널이 우측에서 나온다. 켜고 끄는 옵션은 토글, 값이 필요한 옵션은 입력창이다. 조작할 때마다 하단에 실제 명령어가 실시간으로 조립된다.
- **블록형 파이프라인 빌더:** `[ss -tulpn] → [필터: 8080] → [AI 해설]`처럼 블록을 끌어다 붙이거나 `+`로 잇는다. 블록 종류는 도구, 필터(grep, 정렬, 개수 세기, 열 추출), AI 해설 세 가지다.
- **인텔리센스:** `curl -`까지만 쳐도 사용 가능한 옵션과 한글 설명이 뜨고 탭으로 완성된다.
- **자연어 → 옵션 번역:** "tcpdump로 eth0에서 192.168.0.50으로 가는 패킷 50개만 16진수로"라고 입력하면 `tcpdump -i eth0 dst 192.168.0.50 -c 50 -X`가 실행 대기 상태로 놓인다.

### 5.4 결과 화면

- **상단 브리핑:** AI가 원본 출력을 요약한다. 예: "🟢 포트는 정상 개방, 🔴 HTTP 502. L4가 아닌 L7 애플리케이션 장애입니다."
- **하단 원본:** 고정폭 글꼴의 원본 로그. 접이식이며 고급 등급에서는 기본으로 펼친다.
- 일반사용자에게는 "무엇이 문제이고 무엇을 하면 되는지"만 쉬운 말로 보여 준다.

## 6. 데이터 시각화 4종 [확정]

보이지 않는 패킷을 눈으로 보고 다룰 수 있게 하는 것이 넷엑스의 차별점이다.

### 6.1 패킷 하이웨이 (tcpdump, tshark, 실시간 세션)

- 중앙에 내 PC 노드, 우측에 외부 목적지 노드들을 놓고 선으로 잇는다.
- 패킷은 선을 따라 움직이는 빛나는 입자다.
- 색상: 🟢 녹색은 HTTPS 등 안전한 통신, 🔵 청색은 DNS 질의, 🔴 붉은색은 차단·유실·재전송.
- 선에 마우스를 올리면 현재 속도(Kbps)와 목적지 도메인이 뜬다.

### 6.2 라우팅 노선도 (mtr, traceroute)

- 출발지 → ISP → (해저케이블) → 대상 서버로 이어지는 홉을 지하철 노선도로 그린다. 각 홉은 동그란 역이다.
- 지연 100ms 이하 구간은 얇은 청록색 선이다.
- 지연이 심하거나 손실이 있는 홉과 선은 두꺼운 붉은색으로 바뀌고 맥박처럼 뛴다.
- 붉은 홉을 누르면 우측에 "이 라우터(211.x.x.x)에서 30%가 유실되고 있습니다" 같은 해설이 뜬다.

### 6.3 요새 도면 (ss, lsof, Windows 연결 목록)

- 내 PC를 다각형 요새 도면으로 그린다. 외벽의 문이 열린 포트, 문을 지키는 문지기 뱃지가 그 포트를 점유한 프로세스(PID)다.
- 시스템·브라우저 같은 정상 프로세스의 문은 옅은 푸른빛이다.
- 출처가 불분명하거나 서명이 없는 프로세스의 문에는 🚨 경광등이 번쩍인다.
- 문을 누르면 [강제 종료]와 [방화벽 차단 규칙 등록] 버튼이 나온다.

### 6.4 소나 레이더 (fping, arp-scan)

- 잠수함 소나 화면을 중앙에 크게 둔다. 스캔 중에는 레이더 줄기가 돈다.
- 응답하는 IP를 찾을 때마다 "핑" 소리와 함께 빛나는 점이 찍힌다. 응답이 빠를수록 점이 크고 선명하다.
- 스캔이 끝나면 점들이 장비 카드 목록으로 부드럽게 바뀐다.

### 6.5 시각화 구현 지침

- 입자 렌더링은 HTML5 Canvas와 `requestAnimationFrame`을 쓴다. 입자는 최대 500개로 제한한다.
- 화면 전환은 Framer Motion, 노드 그래프는 D3.js·Vis.js·React Flow 중에서 고른다.
- 대역폭 측정 결과는 계기판 차트로 그린다.

## 7. 넷엑스 터미널 [확정]

넷텀(NetTerm)처럼 Cisco를 비롯한 여러 벤더 장비에 터미널로 접속하는 모듈이다. 시리얼 포트로 실제 장비에 연결되어야 하고, 관련 프로그램들이 가진 기능을 최대한 담는다. 이 모듈이 있으면 Cisco `show` 명령어도 넷엑스 안에서 쓸 수 있다.

### 7.1 접속 방식

| 방식 | 내용 |
|---|---|
| 시리얼 콘솔 | COM 포트, USB-시리얼(콘솔 케이블). 보레이트, 데이터비트, 패리티, 정지비트, 흐름제어 설정. Break 신호 전송(비밀번호 복구, ROMMON 진입) |
| 원격 접속 | SSH(v2, 키 인증, 점프 호스트), Telnet, Rlogin, Raw TCP |
| 파일 전송 | SFTP, SCP, FTP/FTPS 클라이언트. 내장 TFTP 서버(장비 OS 이미지 업그레이드, 설정 백업). 시리얼용 Xmodem/Ymodem/Zmodem |

### 7.2 참고 프로그램에서 가져올 기능

SecureCRT, PuTTY, Xshell, MobaXterm, Tera Term, NetTerm을 기준으로 한다.

- 탭과 화면 분할
- 세션 관리자: 폴더별 장비 목록, 저장된 접속 정보
- 명령 일괄 전송: 여러 장비에 같은 명령을 동시에 보낸다
- 매크로·스크립트, 버튼바(자주 쓰는 명령 원클릭), 자동 로그인
- 세션 로깅(타임스탬프 포함)
- 키워드 하이라이트: `down`, `err-disabled` 등은 붉게
- VT100/xterm 에뮬레이션, 문자 인코딩 선택(UTF-8, EUC-KR)
- SSH 포트 포워딩·터널, X11 포워딩
- 붙여넣기 지연 전송(장비 입력 버퍼 넘침 방지)

### 7.3 AI 결합 기능

- **벤더 자동 인식:** 접속 배너와 프롬프트로 Cisco, Juniper, HPE/Aruba, MikroTik, 국산 장비 등을 판별하고 해당 명령어 자동완성을 켠다.
- **상황 → 장비 명령:** "3번 포트가 안 붙어요"라고 입력하면 `show interface gi0/3`, `show log | include 0/3` 같은 명령을 우선순위·이유·예상 결과와 함께 제안한다. 핵심 루프(2장)와 같은 방식이다.
- **출력 해석:** `show` 결과를 해설하고 표나 시각화로 바꾼다.
- **설정 백업과 비교:** running-config를 저장해 두고 이전 버전과 비교한다(9.1 스냅샷과 연결).
- **위험 명령 보호:** `reload`, `write erase`, `no` 계열은 등급별로 제한하고 실행 전에 확인을 받는다.

### 7.4 구현 메모

- WSL2는 COM 포트에 직접 접근하지 못한다. 시리얼, SSH, TFTP 서버는 **Windows 네이티브(Rust)로 직접 구현**한다.
- 터미널 화면은 xterm.js를 쓴다.
- 후보 라이브러리: 시리얼 `serialport`, SSH `russh` 또는 `ssh2`. 최종 선택은 개발안에서 정한다.

## 8. 스토리방화벽 연동 [확정]

- 스토리방화벽에서 넷엑스를 선택하면 넷엑스가 **별도 창**으로 활성화된다.
- 이 경로로 열리면 사용자 등급과 관계없이 **모든 기능을 사용할 수 있다.**
- 방화벽의 인시던트 카드(악성 IP, 포트, 프로세스)에 [NetX로 정밀 진단] 버튼을 둔다. 누르면 대상 정보가 넷엑스로 넘어와 옴니박스에 자동 입력되고, 추적·차단 제안이 바로 나온다.
- 역할 분담: 방화벽은 감시와 차단에 집중하고, 정밀 추적과 조치는 넷엑스가 맡는다. 예: `mtr`로 공격 경로 역추적, 해당 통신을 일으킨 내부 프로세스 색출과 종료.
- 반대 방향도 연결한다. 요새 도면의 [방화벽 차단 규칙 등록] 버튼은 스토리방화벽에 규칙 등록을 요청한다.

### 8.1 연동 방식과 보안

- 전달 방식: 딥링크(`netx://...`) 또는 로컬 IPC(네임드 파이프).
- **아무 프로그램이나 넷엑스를 전체 권한으로 띄울 수 있으면 그 자체가 공격 통로가 된다.** 그래서 스토리방화벽이 서명한 일회용 토큰(짧은 유효 시간, 재사용 불가)이 확인될 때만 전체 권한 모드를 연다. 검증에 실패하면 일반 모드로 열고 대상 정보만 채운다.
- 전체 권한 모드에서도 프로세스 종료 같은 되돌릴 수 없는 조치는 실행 버튼 확인을 거친다.
- **[검증]** 스토리방화벽 쪽 기술 구성(창 구조, IPC 수단)은 저장소 확인 후 맞춘다.

- "장애는 평소와 무언가 달라졌을 때 발생한다"는 원리다.

| 설정 규정 점검 | 텔넷 허용, 기본 비밀번호 등 취약 설정 경고 |
| 회선 품질 일지 | 정해진 시간마다 속도·지연을 기록해 통신사 품질 증빙으로 활용 |
| 모의 실행 | 실행 전에 "이 명령이 무엇을 바꾸는지" 먼저 보여 준다 |
| 되돌리기 지점 | 장비 설정 변경 전에 자동 백업 |

## 10. 시스템 아키텍처

### 10.1 기술 스택 [확정]

| 층 | 선택 |
|---|---|
| 프론트엔드 | React, TailwindCSS, Framer Motion, Canvas, D3.js/Vis.js/React Flow, xterm.js |
| 백엔드 | Tauri (Rust), `tokio::process::Command` 기반 비동기 스트림 |
| 실행 환경 | Windows 10/11 + WSL2(Ubuntu) |
| AI | 온라인 LLM API + 로컬 Ollama(Tailscale 연결) 하이브리드 |
| 로컬 저장 | 스냅샷, 레시피, 세션 목록, 이력 (SQLite 또는 JSON 파일, 개발안에서 결정) |

초기 설계안에는 프론트엔드를 Vanilla JS로 하는 안도 있었으나, 최종 마스터 가이드 기준인 React로 확정한다.

### 10.2 실행 엔진 이중 구조 (기존 설계안 보완)

기존 설계안은 모든 것을 WSL2로 보냈으나, 그 구조로는 동작하지 않는 기능이 있다.

| 엔진 | 담당 | 이유 |
|---|---|---|
| WSL2 브릿지 | fping, mtr, dig, nc, curl, iperf3, nmap, tshark 등 원격 대상 진단 | 리눅스 도구를 그대로 쓴다. `wsl.exe --exec 도구 인자...` 형태로 호출 |
| Windows 네이티브 | Windows 본체의 포트·프로세스 목록, 프로세스 종료, 호스트 패킷 캡처(pktmon), Wi-Fi 분석 | WSL2 안의 ss/lsof/kill은 WSL 내부 프로세스만 본다. tcpdump도 기본 설정에서는 WSL 가상 인터페이스만 캡처한다 |
| 내장 구현(Rust) | 시리얼, SSH, Telnet, SFTP/FTP, TFTP 서버, 파이프라인 필터 | COM 포트는 WSL2에서 접근 불가. 필터는 셸 없이 처리 |

- 요새 도면과 포트 점유 추적은 **Windows 본체는 네이티브 수집, WSL 내부는 ss/lsof** 두 출처를 합쳐 보여 준다.
- **[검증]** WSL2의 미러 네트워킹 모드를 켜면 WSL에서 호스트 인터페이스 트래픽이 얼마나 보이는지 노트북에서 확인한다.

### 10.3 AI 추론 엔진 [확정]

- **온라인:** 외부 LLM API. 구조화 출력(함수 호출)으로 실행 계획 JSON만 받는다.
- **오프라인(프라이빗):** 로컬 인프라(HP 미니 PC 등)에 Ollama(Phi-3, Llama 3 8B 등, 교체 가능)를 띄우고 Tailscale 폐쇄망으로 연결한다. 인터넷이 끊겨도 AI 분석이 된다. 네트워크 장애를 진단하는 프로그램이므로 이 경로가 필수다.
- **규칙 기반 대체:** 소형 로컬 모델은 구조화된 실행 계획을 안정적으로 내지 못할 수 있다. AI가 둘 다 안 될 때는 키워드로 상황 레시피를 찾아 주는 규칙 엔진으로 내려간다.
- AI의 역할은 세 가지다. ① 상황 → 실행 계획 ② 원본 출력 → 브리핑 ③ 스냅샷 비교 해설.
- 온라인 LLM에 원본 출력을 보낼 때 내부 IP·호스트명을 가리는 옵션과 "로컬 AI만 사용" 설정을 둔다.

## 11. 보안과 구현 제약

### 11.1 명령어 인젝션 차단 [확정]

- 사용자 입력이나 AI 출력을 `sh -c` 같은 셸 문자열로 넘기지 않는다.
- 명령과 인자는 배열로 분리한다. 예: `Command::new("curl").args(["-I", &url])`
- 파이프라인도 셸의 `|`를 쓰지 않는다. Rust에서 앞 프로세스의 stdout을 다음 프로세스의 stdin에 직접 연결하고, grep 같은 필터는 내장 구현으로 처리한다.

### 11.2 실행 전 검증 (기존 설계안 보완)

인자 분리만으로는 부족하다. 정상 옵션만으로도 위험한 동작이 가능하기 때문이다(예: nc의 프로그램 실행 옵션, curl의 파일 쓰기 옵션).

1. **도구 허용 목록:** 레지스트리에 등록된 도구만 실행한다.
2. **옵션 검증:** 모든 인자를 스키마의 타입·범위로 검사한다. IP, 포트, CIDR, 경로는 형식 검증을 거친다.
3. **위험도 계산:** 옵션별 `risk`를 합산해 카드에 배지로 표시한다. `danger`는 추가 확인을 받는다.
4. **경로 제한:** 파일을 쓰는 옵션은 넷엑스 작업 폴더 안으로만 허용한다.
5. **등급 적용:** 등급이 허용하지 않는 도구·옵션은 제안에서 빠지고 실행도 거부된다.
6. **AI 출력 불신:** AI가 만든 계획도 사용자가 직접 조립한 명령과 똑같이 1~5를 통과해야 한다.

### 11.3 비동기 스트림 제어 [확정]

- mtr, tcpdump처럼 계속 출력하는 프로세스는 버퍼를 채워 앱을 멈추게 할 수 있다.
- `tokio::process::Command`로 stdout/stderr를 줄 단위로 읽어 프론트엔드에 이벤트로 흘려보낸다.
- 모든 실행에 중지 버튼, 시간 제한, 출력량 상한을 둔다. 앱 종료 시 자식 프로세스를 정리한다.

### 11.4 WSL2 권한 [확정, 범위 보완]

- tcpdump, lsof, ss의 전체 정보 조회에는 WSL 안의 root 권한이 필요하다.
- 화면에 "WSL2 Root 권한이 필요합니다" 안내와 초기 권한 설정 마법사를 둔다.
- sudoers의 NOPASSWD는 **필요한 바이너리 경로로만 한정**한다. 전체 명령에 무제한으로 열지 않는다.
- 초기 설정 마법사가 함께 하는 일: WSL2·Ubuntu 설치 여부 확인, 도구 일괄 설치.

```
sudo apt update && sudo apt install -y net-tools iproute2 tcpdump tshark mtr fping \
  netcat-openbsd dnsutils lsof iperf3 curl
```

### 11.5 그 밖의 안전 장치

- 장비 접속 계정과 API 키는 Windows 자격 증명 저장소 등 암호화 저장소에 둔다. 저장소(GitHub)와 로그에 남기지 않는다.
- 프로세스 종료, 장비 설정 변경, 스캔 실행은 감사 로그에 기록한다(누가, 언제, 무엇을).
- 스캔·패킷 생성 도구(nmap, masscan, hping3 등)는 **본인이 관리하거나 허가받은 네트워크에서만** 쓰도록 첫 실행 때 안내하고, 사설 대역이 아닌 대상에는 확인을 한 번 더 받는다.

## 13. 개발 환경 [확정]

- 스토리방화벽과 같은 방식으로 **노트북과 GitHub**를 쓴다.
- 저장소: `sysoppark-oss/netx`, **공개**. 공개 저장소는 GitHub Actions 자동 빌드에 분 제한이 없다.
- 비밀 값(LLM API 키, 장비 계정, 방화벽 연동 서명 키)은 코드에 넣지 않는다. GitHub Secrets와 로컬 설정 파일로 관리한다.
- 역할: 코드와 문서 작성은 AI 세션에서, 빌드·실행 검증은 노트북에서 한다. 시리얼 포트, WSL2 브릿지, Windows 네이티브 수집, Tauri 창은 노트북에서만 확인할 수 있다.
- GitHub Actions로 푸시마다 Windows 설치 파일을 자동 빌드한다.

| 단계 | 범위 | 완료 기준 |
|---|---|---|
| v0.1 | 핵심 루프, 도구 레지스트리와 9종 스키마, 등급 5종, 레시피 6종, 옵션 패널, 브리핑·원본 화면, WSL2 브릿지, 보안 검증기, 초기 설정 마법사 | 상황을 입력하면 제안 카드가 나오고 실행 결과와 판정이 보인다 |
| v0.2 | 넷엑스 터미널(시리얼, SSH, Telnet, TFTP, 세션 관리자), Windows 네이티브 수집, 스토리방화벽 연동 | 콘솔 케이블로 실제 장비에 접속하고, 방화벽에서 넷엑스를 호출한다 |
